## What this is

Quando is a Ruby gem: a configurable date parser for non-standard, multi-language human-written dates (e.g. `"01 января 2019 г."`, `"1-ЯНВ-19"`) that `Date.strptime` can't handle. Parsing is driven entirely by user-supplied regular expressions. Supports Ruby >= 3.3.

## Commands

All commands run inside the Nix dev shell (`nix develop`), which provides Ruby 3.4 and sets `BUNDLE_PATH=vendor/bundle`. Gems must only ever be installed locally into `./vendor/bundle` — never system-wide.

```bash
nix develop           # enter the dev shell (or prefix one-offs: nix develop -c <cmd>)
bundle install        # install dependencies (into ./vendor/bundle)
bundle exec rake      # run the full spec suite (default rake task)
bundle exec rspec     # same, via rspec directly
bundle exec rspec spec/quando_spec.rb:42   # run the single example at line 42
bin/console           # IRB session with quando loaded
```

There is no separate lint step; `.editorconfig` defines the style.

## Architecture

Three layers, all under `lib/quando/`:

- **`Quando` module** (`lib/quando.rb`) — the public entry point. `Quando.parse(date, opts)` builds a throwaway `Parser`, optionally overrides `:matcher` (one regexp or an array, assigned to `formats`) and `:century`, then parses. These per-call overrides never touch global config.

- **`Quando::Config`** (`lib/quando/config.rb`) — holds all the regexp matchers. The key design is **compound matchers that auto-rebuild**: part matchers in `AUTOUPDATE` (`day`, `month_num`, `year`, `year2`, the 12 month regexps, `dlm`) get setters generated by a metaprogramming loop; whenever one changes, `uniupdate!` regenerates the two `COMPOUND` matchers — `month_txt` (an OR of all 12 month regexps) and `formats` (the ordered array of full date-format regexps). So configuring a single month name transparently updates the combined matchers. `Quando.config` is a memoized class-level singleton; `Quando.reset!` rebuilds it.

- **`Quando::Parser`** (`lib/quando/parser.rb`) — the matching engine. `parse` tries each regexp in `config.formats` **in order** and uses the first whose extracted day/month/year are all valid. Two concepts govern extraction per date part:
  - `wanted?` — does the matched format's regexp define a named capture (`day`/`month`/`year`)? If not, a default is used: day → 1, month → 1, year → current UTC year.
  - `found?` — did that named capture actually match text?

  Month detection maps a captured month string to 1–12 by finding the first `Config::MONTHS` entry whose regexp matches it, falling back to numeric interpretation. Two-digit years are expanded via `config.century` (default 21 → 2000s) in `century_to_hundreds`.

### Important conventions

- Format and part matchers **must** use the named captures `day`, `month`, `year` for the parser to read them. Avoid these three names for any other groups in custom regexps — they collide with the parser's internal use.
- `Parser#configure` dups the global config so instance-level configuration is isolated; calling setters on `Quando.config` directly mutates global state.
- When adding or changing matchers in `Config`, go through the generated setters (or call `uniupdate!`) so the compound matchers stay in sync — don't set the `@ivar` directly.

The README is the canonical, detailed reference for configuration semantics and parsing rules.
